## T-20: Replace the inline prompts with dialogs for passphrase, host key and auth errors
**Fase:** F4  **Depende de:** T-19
**Contexto:** Sustituye los avisos inline provisionales de T-17c (`TabPrompt`) por diálogos modales accesibles. Los campos de secreto **permiten pegar** (atajo y menú contextual) y **no permiten copiar/cortar**. La passphrase nunca se prellena ni se ofrece "recordar": la retención en memoria es automática y por pestaña (T-17a). En error de auth con contraseña guardada, se vuelve a pedir y se ofrece actualizar la guardada.

**Archivos a crear/modificar:**
- `ui/src/dialogs/SecretDialog.tsx` (crear: contraseña o passphrase; `<dialog>` nativo con `showModal`)
- `ui/src/dialogs/HostKeyDialog.tsx` (crear: huella nueva → Aceptar/Cancelar; huella cambiada → solo aviso y Cerrar)
- `ui/src/tabs/TabPrompt.tsx` (modificar: delega en los diálogos; `dropped`/`error` siguen inline con Reconectar/Reintentar)
- `ui/src/tabs/tabState.ts` (modificar solo si hace falta para distinguir `auth_rejected` con contraseña guardada)
- `ui/src/dialogs/dialogs.test.tsx` (crear)

**Interfaces / firmas esperadas:**
```ts
export interface SecretDialogProps { kind: "password" | "passphrase"; offerRemember: boolean;   // offerRemember solo para "password" y sesión guardada
  onSubmit(value: string, remember: boolean): void; onCancel(): void }
export function SecretDialog(props: SecretDialogProps): JSX.Element;
export interface HostKeyDialogProps { fingerprint: string; changed: boolean; host: string; onAccept(): void; onCancel(): void }
export function HostKeyDialog(props: HostKeyDialogProps): JSX.Element;
```
- Campo de secreto: `type="password"`, `autoComplete="off"`, `onCopy`/`onCut` con `preventDefault`; **sin** handler que bloquee `paste`. El valor se borra del estado justo tras `onSubmit`.
- `kind = "passphrase"` → `offerRemember` se ignora: nunca hay casilla.
- Error `auth_rejected` en una pestaña con `sessionId` y contraseña guardada → `SecretDialog` con `offerRemember: true`; enviar con "recordar" → `connect({ password })` y, si conecta, `updateSession(id, input, { kind: "set", value })` para actualizar la guardada.
- `host_key_changed` → `HostKeyDialog changed` sin botón de aceptar (no hay forma de confiar desde la UI).
- `Escape` o Cancelar en un diálogo de huella nueva → `controller.close()`; en el de secreto → la pestaña queda en `error` con "Reintentar".

**Criterios de aceptación (Vitest + Testing Library):**
- [ ] El campo de passphrase está vacío al abrir; no existe casilla "recordar" para passphrase.
- [ ] Pegar en el campo (evento `paste` + cambio de valor) funciona: el evento no tiene `defaultPrevented`.
- [ ] `copy` y `cut` sobre el campo quedan con `defaultPrevented`.
- [ ] Tras enviar, el campo queda vacío y el componente no conserva el valor.
- [ ] Huella nueva: "Aceptar" reintenta con `approvedFingerprint`; huella cambiada: no hay botón "Aceptar".
- [ ] `auth_rejected` con contraseña guardada → diálogo con "Recordar"; reintento con contraseña nueva + recordar → `updateSession` con `{ kind: "set" }`.
- [ ] Los tests de `TabsView` de T-17c siguen pasando (ajusta solo selectores si cambian etiquetas).
- [ ] `just check` en verde.
- [ ] (Manual, humano) pegar una passphrase con Ctrl/Cmd+V y con el menú contextual.

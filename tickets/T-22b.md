## T-22b: Add the transfer queue and safe local target resolution in the application layer
**Fase:** F5  **Depende de:** T-22a
**Contexto:** La cola de transferencias y la política de nombres son lógica de aplicación pura (sin tokio): `desktop` (T-22c) ejecuta un worker que saca trabajos de la cola y llama a `FileTransfer`. Al descargar, el nombre del archivo viene del **servidor** (no confiable): hay que impedir el path traversal al construir la ruta local.

**Archivos a crear/modificar:**
- `crates/application/src/lib.rs` (modificar: `pub mod transfer_queue;`)
- `crates/application/src/transfer_queue.rs` (crear: `TransferQueue`, `TransferJob`, `local_download_target` + tests)

**Interfaces / firmas esperadas:**
```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)] pub struct TransferId(u64);       // new/get
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum TransferKind { Download { remote: RemotePath, local: PathBuf }, Upload { local: PathBuf, remote: RemotePath } }
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum TransferState { Queued, Running { transferred: u64, total: Option<u64> }, Done { bytes: u64 }, Failed(TransferError), Cancelled }
#[derive(Debug, Clone)]
pub struct TransferJob { pub id: TransferId, pub conn: ConnectionId, pub kind: TransferKind, pub state: TransferState, pub cancel: CancelToken }

#[derive(Default)]
pub struct TransferQueue { jobs: Vec<TransferJob>, next_id: u64 }
impl TransferQueue {
    pub fn enqueue(&mut self, conn: ConnectionId, kind: TransferKind) -> TransferId;
    pub fn start_next(&mut self) -> Option<TransferJob>;          // primer Queued → Running{0, None}; None si ya hay uno Running (1 a la vez) o no hay Queued
    pub fn progress(&mut self, id: TransferId, transferred: u64, total: Option<u64>);
    pub fn finish(&mut self, id: TransferId, result: Result<u64, TransferError>);   // Ok → Done; Err(Cancelled) → Cancelled; Err(e) → Failed(e)
    pub fn cancel(&mut self, id: TransferId) -> bool;            // Queued → Cancelled directamente; Running → cancel.cancel() (el worker termina con Cancelled); otros → false
    pub fn cancel_connection(&mut self, conn: ConnectionId);     // al desconectar: cancela todos los de esa conexión
    pub fn clear_finished(&mut self);                            // quita Done/Failed/Cancelled
    pub fn jobs(&self) -> &[TransferJob];
}
/// Ruta local segura para descargar `remote` dentro de `dir`.
pub fn local_download_target(dir: &Path, remote: &RemotePath) -> Result<PathBuf, TransferError>;
```
**Reglas de `local_download_target`:**
- Usa solo el último componente de la ruta remota.
- Lo rechaza con `TransferError::LocalIo` si: está vacío; es `.` o `..`; contiene `/`, `\`, `:` o NUL; o es un nombre reservado de Windows (`CON`, `PRN`, `AUX`, `NUL`, `COM1`–`COM9`, `LPT1`–`LPT9`, con o sin extensión, sin distinguir mayúsculas).
- Quita espacios y puntos finales (Windows).
- El resultado es `dir.join(nombre)`, y un test comprueba que `starts_with(dir)`.

**Criterios de aceptación (unit, sin runtime):**
- [ ] FIFO: tres `enqueue` → `start_next` devuelve el primero; mientras haya uno `Running`, `start_next` → `None`; tras `finish`, devuelve el siguiente.
- [ ] `finish` con `Ok`, `Err(Cancelled)` y `Err(Remote)` → `Done`, `Cancelled`, `Failed(Remote)`.
- [ ] `cancel` de un `Queued` → `Cancelled` y `start_next` lo salta; de un `Running` → su `CancelToken` queda cancelado.
- [ ] `cancel_connection` cancela solo los trabajos de esa conexión.
- [ ] `progress` actualiza solo el trabajo `Running` indicado.
- [ ] `local_download_target`: `/srv/a.txt` → `dir/a.txt`; `..`, `a\b`, `C:x`, `CON`, `con.txt`, `nul ` y vacío → error; `report. ` → `dir/report`.
- [ ] `application` solo depende de `tuki-core` y `thiserror`. `just check` en verde.

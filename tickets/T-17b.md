## T-17b: Add the tab state machine and per-tab session controller in the UI
**Fase:** F3  **Depende de:** T-17a
**Contexto:** Cada pestaña tiene un estado (conectando, conectado, pide algo, caído, error) y un controlador que habla con `api.ts`. Los bytes del PTY **no** pasan por React: el controlador implementa `TerminalSource` (T-16) y guarda en un buffer los bytes que llegan antes de que se monte la vista; los vacía al hacer `attach`. Sin componentes en este ticket (T-17c).

**Archivos a crear/modificar:**
- `ui/src/lib/api.ts` (modificar: `connect(tabId, args, handlers)` envía `tabId`; nuevo `closeTab(tabId)` → `invoke("close_tab", { tabId })`)
- `ui/src/lib/api.test.ts` (modificar: ajustar a la nueva firma + test de `closeTab`)
- `ui/src/tabs/tabState.ts` (crear: tipos + reducer puro)
- `ui/src/tabs/tabController.ts` (crear: controlador por pestaña)
- `ui/src/tabs/tabs.test.ts` (crear)

**Interfaces / firmas esperadas:**
```ts
// tabState.ts
export type ConnectTarget = Omit<ConnectArgs, "password" | "passphrase" | "approvedFingerprint" | "rows" | "cols">;
export type TabStatus =
  | { kind: "connecting" }
  | { kind: "connected"; connectionId: number; channelId: number }
  | { kind: "needs_password" } | { kind: "needs_passphrase" }
  | { kind: "needs_host_key_approval"; fingerprint: string }
  | { kind: "dropped"; exitStatus: number | null }
  | { kind: "error"; error: CommandError };
export interface Tab { id: number; title: string; target: ConnectTarget; status: TabStatus }
export type TabAction =
  | { type: "opened"; tab: Tab } | { type: "connecting"; id: number }
  | { type: "resolved"; id: number; response: ConnectResponse }
  | { type: "failed"; id: number; error: CommandError }
  | { type: "remote_closed"; id: number; exitStatus: number | null }
  | { type: "closed"; id: number };
export function tabsReducer(tabs: readonly Tab[], action: TabAction): Tab[];   // acciones de un id inexistente → sin cambios

// tabController.ts
export interface ConnectSecrets { password?: string; passphrase?: string; approvedFingerprint?: string }
export interface TabController extends TerminalSource {
  connect(secrets: ConnectSecrets, size: { rows: number; cols: number }): Promise<void>;  // dispatch connecting → resolved | failed
  reconnect(size: { rows: number; cols: number }): Promise<void>;                          // = connect({}, size): el backend reutiliza la passphrase retenida
  close(): Promise<void>;                                                                  // disconnect (si hay conexión) + closeTab(tabId) + dispatch closed; errores de disconnect se ignoran
}
export function createTabController(tab: Pick<Tab, "id" | "target">, dispatch: (action: TabAction) => void): TabController;
```
- Errores del `invoke` se estrechan con `isCommandError`; si no lo son → `{ kind: "io", message: "Error inesperado" }`.
- Los secretos solo viven en la llamada a `connect`: el controlador **no** los guarda (ni en el estado ni en campos).
- Buffer de bytes previos al `attach` con tope de 1 MiB (descarta lo más antiguo); `ponytail:` comment con el tope.
- Sin `any`.

**Criterios de aceptación (Vitest, `vi.mock("../lib/api")`):**
- [ ] Reducer: `connecting → connected` con ids; `→ needs_password/needs_passphrase/needs_host_key_approval`; `failed → error`; `remote_closed → dropped` con `exitStatus`; `closed` quita la pestaña; id inexistente no cambia nada.
- [ ] `connect` despacha `connecting` y luego `resolved`; un rechazo con `CommandError` despacha `failed` con ese error.
- [ ] `onClosed` del backend despacha `remote_closed`.
- [ ] Bytes que llegan antes de `attach` se entregan en orden al hacer `attach`; después llegan directo; tras `detach` no se entregan.
- [ ] `reconnect` llama a `api.connect` sin `password` ni `passphrase`.
- [ ] `close` llama a `disconnect(connectionId)` y a `closeTab(tabId)`, aunque `disconnect` falle.
- [ ] El estado (JSON del reducer) nunca contiene la contraseña ni la passphrase pasadas a `connect`.
- [ ] `just check` en verde.

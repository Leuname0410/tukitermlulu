## T-05a: Add the OpenSSH test container and the Ed25519 fixture key
**Fase:** F0  **Depende de:** T-04
**Contexto:** Servidor OpenSSH reproducible en Docker para los tests de integración (`adapters`). Host key fija y `known_hosts` propio para que los tests **nunca** desactiven la verificación de la llave del host. Solo material de prueba: nunca usarlo fuera de tests.

**Archivos a crear:**
- `tests/fixtures/Dockerfile`
- `tests/fixtures/docker-compose.yml`
- `tests/fixtures/known_hosts`
- `.gitattributes`
- `tests/fixtures/README.md`
(+ generados con `ssh-keygen`, sin passphrase: `tests/fixtures/ed25519` + `ed25519.pub` (cliente, comentario `tuki-test`), `tests/fixtures/host/ssh_host_ed25519_key` + `.pub` (servidor))

**Estructura esperada:**
- `Dockerfile`: `FROM alpine:3.22` (tag fijo), instala `openssh`; crea usuario `tuki` con shell `/bin/sh` y contraseña `tuki-test`; copia `ed25519.pub` a `/home/tuki/.ssh/authorized_keys` (dueño `tuki`, 0700/0600); copia la host key a `/etc/ssh/` (0600) y configura `sshd_config` con **solo** `HostKey /etc/ssh/ssh_host_ed25519_key`, `PasswordAuthentication yes`, `PubkeyAuthentication yes`, `PermitRootLogin no`. `CMD ["/usr/sbin/sshd", "-D", "-e"]`, `EXPOSE 22`.
- `docker-compose.yml`: servicio `sshd`, `build: .`, puertos `127.0.0.1:2222:22` (solo loopback), `healthcheck` que compruebe que sshd escucha.
- `known_hosts`: una línea `[127.0.0.1]:2222 <contenido de host/ssh_host_ed25519_key.pub sin comentario>`.
- `.gitattributes`: `tests/fixtures/** text eol=lf` (las llaves no deben convertirse a CRLF en Windows).
- `README.md` (≤ 25 líneas, español): qué contiene, usuario/contraseña de prueba, puerto, cómo levantar/bajar, aviso "solo para tests", y que **no se regenera** (si se regenera, actualizar `known_hosts`).

**Criterios de aceptación (verificables):**
- [ ] `docker compose -f tests/fixtures/docker-compose.yml up -d --build` levanta el contenedor y queda `healthy`.
- [ ] `ssh -i tests/fixtures/ed25519 -p 2222 -o UserKnownHostsFile=tests/fixtures/known_hosts -o StrictHostKeyChecking=yes -o IdentitiesOnly=yes tuki@127.0.0.1 echo ok` imprime `ok` (verificación de host **activa**).
- [ ] El puerto solo escucha en `127.0.0.1`.
- [ ] Tras `git add`, `git ls-files --eol tests/fixtures` muestra `i/lf` en todas las llaves.
- [ ] `just check` sigue en verde.

**Tests requeridos:** ninguno automatizado (los criterios son comandos de verificación; los tests de integración llegan con T-13).
**Commit:** `test(fixtures): add openssh container and ed25519 fixture key [T-05a]`

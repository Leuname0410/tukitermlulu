## T-05b: Add PEM and PPK key fixtures for every supported format
**Fase:** F0  **Depende de:** T-05a
**Contexto:** Fixtures de llaves para el spike T-06 y el `KeyLoader` (T-09): PEM (OpenSSH / PKCS#1 / PKCS#8) y PPK v2/v3, con y sin passphrase. Todas autorizadas en el contenedor para poder probar la conexión real.

**Archivos a crear/modificar:**
- `tests/fixtures/gen-keys.sh` (crear: script que documenta y reproduce la generación)
- `tests/fixtures/Dockerfile` (modificar: `authorized_keys` incluye todas las `.pub`)
- `tests/fixtures/README.md` (modificar: tabla de llaves)
(+ generados en `tests/fixtures/keys/`: las llaves y sus `.pub`)

**Llaves esperadas** (passphrase común de prueba: `tuki-pass`):
| archivo | formato |
|---|---|
| `keys/rsa_openssh`, `keys/rsa_openssh_pass` | OpenSSH, RSA 3072 |
| `keys/rsa_pkcs1.pem` | PEM PKCS#1 (`-m PEM`), RSA 3072 |
| `keys/rsa_pkcs8.pem` | PEM PKCS#8 (`-m PKCS8`), RSA 3072 |
| `keys/ecdsa_p256`, `keys/ecdsa_p256_pass` | OpenSSH, ECDSA P-256 |
| `keys/ed25519_pass` | OpenSSH, Ed25519 con passphrase |
| `keys/ed25519_v2.ppk`, `keys/ed25519_v2_pass.ppk` | PPK v2 |
| `keys/ed25519_v3.ppk`, `keys/ed25519_v3_pass.ppk` | PPK v3 (Argon2id) |
| `keys/rsa_v3.ppk` | PPK v3, RSA |
Cada llave con su `.pub` en formato OpenSSH (comentario `tuki-test-<nombre>`). El `ed25519` de T-05a no se toca.

**Estructura esperada:**
- `gen-keys.sh` (POSIX sh, `set -eu`): genera las llaves OpenSSH/PEM con `ssh-keygen` y las PPK con `puttygen` **dentro de un contenedor** (`docker run --rm -v ...:/k alpine:3.22 sh -c 'apk add --no-cache putty openssh-keygen && ...'`), usando `--ppk-param version=2|3`. Idempotente: si `keys/` ya existe, aborta con mensaje (no regenera).
- `Dockerfile`: concatena `ed25519.pub` y `keys/*.pub` en `authorized_keys`; añade al `sshd_config` la línea `Subsystem sftp internal-sftp` (pendiente de T-05a, necesaria para SFTP).
- `README.md`: tabla anterior + la passphrase de prueba + "no regenerar".

**Criterios de aceptación (verificables):**
- [ ] Existen todas las llaves de la tabla; `ssh-keygen -y -f <llave> [-P tuki-pass]` funciona para cada llave no-PPK.
- [ ] `puttygen <ppk> -O fingerprint` (en contenedor) funciona para cada PPK, y las v3 muestran `PPK-File-Version`/`Key-Derivation: Argon2id` en la cabecera.
- [ ] Tras reconstruir el contenedor, `ssh -i tests/fixtures/keys/ecdsa_p256 ...` (mismas opciones que T-05a, host key verificada) imprime `ok`.
- [ ] `sftp -i tests/fixtures/ed25519 -P 2222 -o UserKnownHostsFile=tests/fixtures/known_hosts -o StrictHostKeyChecking=yes tuki@127.0.0.1` con `ls` en batch (`-b`) funciona.
- [ ] `git ls-files --eol tests/fixtures/keys` muestra `i/lf`.
- [ ] `just check` sigue en verde.

**Tests requeridos:** ninguno automatizado (verificación por comandos; el uso real llega en T-06/T-09).

- Handler de russh: `check_server_key` guarda `key.fingerprint(HashAlg::Sha256)` formateado como `SHA256:<base64>` y **acepta** el handshake; `connect` devuelve `Connected { id, fingerprint }`. La conexión no está autenticada: ningún dato del usuario viaja antes de `authenticate`.
- `authenticate`: `Credential::Password(s)` → `authenticate_password(user, s.expose())`; `Credential::PublicKey(k)` → `decode_secret_key(<k como &str>, None)` + `PrivateKeyWithHashAlg` con el mejor hash RSA que anuncie el servidor (`best_supported_rsa_hash`). Rechazo del servidor → `AuthenticationRejected`; fallo de protocolo/red → `Authentication`/`Io`. El usuario se toma de `Host` guardado en la conexión.
- Errores de russh mapeados sin texto del servidor ni secretos.
- `justfile`: `test-int: docker compose -f tests/fixtures/docker-compose.yml up -d --build --wait` y luego `cargo test -p tuki-adapters --features integration -- --test-threads=1`.

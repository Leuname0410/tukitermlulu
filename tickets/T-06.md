## T-06: Spike — verify russh can load every fixture key format
**Fase:** F1  **Depende de:** T-05b
**Contexto:** Antes de fijar el `KeyLoader` (T-09) hay que saber qué formatos carga `russh` de serie (PEM OpenSSH/PKCS#1/PKCS#8, PPK v2/v3 con Argon2). El resultado alimenta ADR-003 (lo redacta el revisor; tú solo escribes el informe). Código de spike: solo tests, nada de producción.

**Archivos a crear/modificar:**
- `crates/adapters/Cargo.toml` (modificar: `[dev-dependencies] russh = "<última estable>"`; si una llave falla, añade también `ssh-key = { version = "<última>", features = ["ppk", "encryption"] }` como dev-dependency para comparar)
- `crates/adapters/tests/spike_key_formats.rs` (crear)
- `docs/spikes/T-06-key-formats.md` (crear: informe ≤ 40 líneas)

**Estructura esperada:**
- Un test por llave de `tests/fixtures/keys/` + `tests/fixtures/ed25519` (ver `tests/fixtures/README.md`), nombre `should_load_<llave>_when_using_russh`. Con passphrase `tuki-pass` cuando aplique.
- Un test negativo por formato con passphrase incorrecta: `should_fail_<llave>_when_passphrase_is_wrong`; se registra qué error devuelve (variante y mensaje).
- Si `russh` no soporta un formato, el test de russh se marca `#[ignore = "unsupported by russh: <motivo>"]` y se añade el test equivalente con `ssh-key` (plan B).
- Informe: tabla `llave | russh | ssh-key (si se probó) | error con passphrase mala`, versiones exactas usadas, y una recomendación de una línea.

**Criterios de aceptación (verificables):**
- [ ] Existe un test por cada llave de fixture (13: 12 en `keys/` + `ed25519`) y uno negativo por formato con passphrase.
- [ ] Ningún test se salta sin `#[ignore = "<motivo>"]` explícito.
- [ ] El informe cubre todas las llaves y fija las versiones.
- [ ] `just check` en verde (los `#[ignore]` no cuentan como fallo).

**Tests requeridos:** integración (lectura de archivos de fixture; sin red).
**Commits:** `test(adapters): spike key format loading [T-06]` → `docs(spike): key format report [T-06]`

**Fuera de alcance:** el `KeyLoader` real, conexión SSH, cambios en `core`/`application`, ADRs.

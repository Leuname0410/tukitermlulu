## T-22a: Add the FileTransfer port and streaming SFTP download/upload with progress and cancellation
**Fase:** F5  **Depende de:** T-21 · **ADR:** 002
**Contexto:** Transferir archivos de cualquier tamaño **sin cargarlos en memoria**: copia por bloques de tamaño fijo, con progreso y cancelación. Se escribe en un temporal `.part` y se renombra al terminar; si se cancela o falla, el parcial se borra. El puerto vive en `core` (sin tokio: el progreso es un trait síncrono y la cancelación un `AtomicBool`, como `PtySink` en ADR-005).

**Archivos a crear/modificar:**
- `crates/core/src/ports.rs` (modificar: `FileTransfer`, `TransferProgress`, `CancelToken`)
- `crates/core/src/port_errors.rs` (modificar: `TransferError`)
- `crates/adapters/src/sftp.rs` (modificar: `impl FileTransfer for RusshFileSystem`)
- `crates/adapters/tests/sftp_transfer.rs` (crear: integración, `#![cfg(feature = "integration")]`)

**Interfaces / firmas esperadas:**
```rust
// core/ports.rs
pub trait TransferProgress: Send + Sync { fn progress(&self, transferred: u64, total: Option<u64>); }   // síncrono y barato
#[derive(Clone, Default)] pub struct CancelToken(Arc<AtomicBool>);   // cancel(), is_cancelled()
#[cfg_attr(any(test, feature = "mocks"), mockall::automock)]
pub trait FileTransfer: Send + Sync {
    fn download<'a>(&'a self, conn: ConnectionId, remote: &'a RemotePath, local: &'a Path,
        progress: &'a dyn TransferProgress, cancel: &'a CancelToken) -> impl Future<Output = Result<u64, TransferError>> + Send + 'a;
    fn upload<'a>(&'a self, conn: ConnectionId, local: &'a Path, remote: &'a RemotePath,
        progress: &'a dyn TransferProgress, cancel: &'a CancelToken) -> impl Future<Output = Result<u64, TransferError>> + Send + 'a;
}
// core/port_errors.rs
pub enum TransferError { Cancelled, NotFound, PermissionDenied, AlreadyExists, LocalIo, Remote }   // mensajes literales, sin rutas
```
**Reglas del adaptador:**
- Bloque fijo de 256 KiB reutilizado (`ponytail:` con el tamaño); nunca `read_to_end`/`Vec` del archivo entero. I/O local con `tokio::fs` (nada bloqueante en async).
- `download`: destino existente → `AlreadyExists` (no se sobrescribe); escribe en `<local>.part` y `rename` al final; `total` = tamaño del `stat` remoto.
- `upload`: destino remoto existente → `AlreadyExists`; escribe en `<remote>.part` y `rename` remoto al final.
- Cancelación comprobada entre bloques → borra el `.part` y devuelve `Cancelled`. Cualquier error a mitad → borra el `.part` y devuelve el error.
- `progress` se llama como mucho una vez por bloque y una al final con el total.
- Devuelve los bytes transferidos. Sin `unwrap`/`expect`.

**Criterios de aceptación (integración contra el contenedor, `just test-int`):**
- [ ] Subir un archivo local de 32 MiB (generado en `tempfile`, contenido pseudoaleatorio con semilla) y descargarlo de vuelta → mismos bytes (comparar hash por bloques, sin cargar ambos enteros).
- [ ] `progress` recibe valores crecientes y termina en el tamaño total.
- [ ] Cancelar durante la descarga (el `TransferProgress` del test llama a `cancel()` tras el primer bloque) → `Cancelled` y no quedan ni el destino ni el `.part` locales.
- [ ] Cancelar durante la subida → `Cancelled` y `stat` remoto del destino y del `.part` → no existen.
- [ ] Destino existente (local y remoto) → `AlreadyExists` sin modificarlo.
- [ ] Descargar una ruta remota inexistente → `NotFound`; subir a `/root/x` → `PermissionDenied`.
- [ ] Test unitario en `core`: `CancelToken` clonado comparte el estado.
- [ ] `just check` y `just test-int` en verde.
- [ ] (Manual, humano) 1 GB sin que la memoria del proceso crezca más que unos pocos MiB.

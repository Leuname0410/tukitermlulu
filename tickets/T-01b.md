## T-01b: Add the `application` and `adapters` crates
**Fase:** F0  **Depende de:** T-01a
**Contexto:** Segunda parte del scaffold. Crates vacíos que fijan la dirección de dependencias `adapters → application → core`. El workspace usa `members = ["crates/*"]`, así que el `Cargo.toml` raíz no se toca.

**Archivos a crear:**
- `crates/application/Cargo.toml`
- `crates/application/src/lib.rs`
- `crates/adapters/Cargo.toml`
- `crates/adapters/src/lib.rs`
(+ `Cargo.lock` actualizado por cargo)

**Estructura esperada:**
- Ambos `Cargo.toml` heredan `edition/license/version/rust-version` con `.workspace = true` (igual que `crates/core/Cargo.toml`).
- `crates/application/Cargo.toml`: `name = "tuki-application"`; única dependencia `tuki-core = { path = "../core" }`.
- `crates/adapters/Cargo.toml`: `name = "tuki-adapters"`; dependencias `tuki-core = { path = "../core" }` y `tuki-application = { path = "../application" }`. Nada más.
- Cada `lib.rs`: solo un doc comment de crate en español:
  - application: `//! Casos de uso. Depende solo de los puertos de tuki-core.`
  - adapters: `//! Implementaciones de los puertos (russh, sftp, keyring, sqlite, known_hosts).`

**Criterios de aceptación (verificables):**
- [ ] `cargo build --workspace` compila los 3 crates.
- [ ] `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings` y `cargo test --workspace` en verde.
- [ ] `cargo tree -p tuki-application` muestra solo `tuki-core`.
- [ ] `cargo tree -p tuki-adapters` muestra solo `tuki-application` y `tuki-core`.

**Tests requeridos:** ninguno (scaffold sin lógica).
**Commit:** `chore(app): add application and adapters crates [T-01b]`

**Fuera de alcance:** crate `desktop`, UI, cambios al `Cargo.toml` raíz, dependencias externas.

## T-21: Implement RemoteFileSystem with russh-sftp over the terminal's SSH connection
**Fase:** F5  **Depende de:** T-20 · **ADR:** 002
**Contexto:** El sidebar SFTP usa **la misma conexión SSH** que la terminal: no se vuelve a autenticar ni a pedir secretos. Cada `ConnectionId` abre de forma perezosa un canal con el subsistema `sftp` y lo reutiliza.

**Archivos a crear/modificar:**
- `crates/adapters/Cargo.toml` (modificar: `russh-sftp`, última versión compatible con russh 0.65.4 y MSRV 1.100; sin activar features innecesarias)
- `crates/adapters/src/lib.rs` (modificar: `pub mod sftp;`)
- `crates/adapters/src/ssh_transport.rs` (modificar: `pub(crate) async fn open_subsystem(&self, conn: ConnectionId, name: &str) -> Result<Channel<Msg>, TransportError>`; bloquea el handle de la conexión solo durante `channel_open_session`, igual que `open_pty`)
- `crates/adapters/src/sftp.rs` (crear: `RusshFileSystem`)
- `crates/adapters/tests/sftp.rs` (crear: integración, `#![cfg(feature = "integration")]`)
(+ `Cargo.lock`)

**Interfaces / firmas esperadas:**
```rust
#[derive(Clone)]
pub struct RusshFileSystem { transport: RusshTransport, sessions: Arc<tokio::sync::Mutex<HashMap<ConnectionId, Arc<SftpSession>>>> }
impl RusshFileSystem { pub fn new(transport: RusshTransport) -> Self; }
impl RemoteFileSystem for RusshFileSystem { list, stat, rename, remove, mkdir }
```
**Reglas:**
- `session(conn)`: devuelve la `SftpSession` cacheada o abre `open_subsystem(conn, "sftp")` → `request_subsystem` → `SftpSession::new(channel.into_stream())`. El mapa se bloquea solo para leer/insertar, **nunca** durante una operación SFTP.
- Conexión inexistente → `FsError::Operation`. Si una operación falla porque el canal se cerró, se quita la entrada de la caché (la siguiente llamada reabre).
- `list`: omite `.` y `..`; cada `FileEntry.path = path.join(name)`; un nombre que `RemotePath::join` rechace (p. ej. con `/`) se omite, no se propaga.
- `remove`: `stat` → archivo: `remove_file`; directorio: `remove_dir` (no recursivo; un directorio con contenido → `Operation`).
- Mapeo de errores SFTP: `NoSuchFile` → `NotFound`; `PermissionDenied` → `PermissionDenied`; resto → `Operation`. Sin rutas ni detalles en los mensajes.
- Sin `unwrap`/`expect` en producción.

**Criterios de aceptación (integración contra el contenedor `127.0.0.1:2222`, `just test-int`):**
- [ ] Conectar y autenticar con `RusshTransport` (password) y usar `RusshFileSystem::new(transport.clone())` sin volver a autenticar.
- [ ] `mkdir` en `/home/tuki/<único>` → `list` del padre la contiene con `is_dir = true`; `stat` → `is_dir = true`.
- [ ] Subir un archivo con `printf` por el PTY no es necesario: crea uno con `mkdir`+`rename` de directorios, o escribe vía la sesión SFTP del propio test si `russh-sftp` lo expone; verifica `size` en `stat` de un archivo existente del sistema (p. ej. `/etc/hostname`).
- [ ] `rename` y luego `stat` del nombre viejo → `NotFound`.
- [ ] `remove` de un directorio vacío y de un archivo → `stat` → `NotFound`; `remove` de directorio no vacío → `Operation`.
- [ ] `list("/root")` → `PermissionDenied`; `stat` de una ruta inexistente → `NotFound`.
- [ ] La terminal y el SFTP funcionan a la vez sobre la misma conexión (abrir PTY, luego `list`, luego `write` en el PTY sin error).
- [ ] `close(conn)` del transporte → la siguiente operación SFTP falla con `Operation` sin panic.
- [ ] `just check` y `just test-int` en verde; `cargo deny`/`audit` aceptan la nueva dependencia.

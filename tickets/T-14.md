## T-14: Implement the ConnectSession use case
**Fase:** F3  **Depende de:** T-13c · **ADR:** 004 (secretos), 005 (handshake verificado)
**Contexto:** Orquesta una conexión completa: handshake → verificación TOFU de la huella **antes** de enviar credenciales → credencial (contraseña tecleada o guardada; llave + passphrase) → autenticación → PTY. Cuando falta una decisión o un secreto del usuario, cierra la conexión y devuelve qué hace falta (la UI pregunta y reintenta). Ante cualquier error tras `connect`, cierra la conexión (best-effort).

**Interfaces / firmas esperadas:**
```rust
pub struct ConnectSession<T: SshTransport, V: HostKeyVerifier, K: KeyLoader, S: SecretStore> { transport: T, verifier: V, keys: K, secrets: S }
impl<..> ConnectSession<T, V, K, S> {
    pub fn new(transport: T, verifier: V, keys: K, secrets: S) -> Self;
    pub async fn execute(&self, request: ConnectRequest<'_>) -> Result<ConnectOutcome, ConnectError>;
}
pub struct ConnectRequest<'a> {
    pub session: &'a Session,
    pub password: Option<&'a SecretString>,             // tecleada ahora; si es None y `remember`, se busca en SecretStore
    pub passphrase: Option<&'a SecretString>,           // de la UI o de la memoria de la pestaña (T-17)
    pub approved_fingerprint: Option<&'a HostKeyFingerprint>, // el usuario aceptó esta huella (TOFU)
    pub pty_size: PtySize,
    pub sink: Box<dyn PtySink>,
}
pub enum ConnectOutcome {
    Connected { connection: ConnectionId, channel: ChannelId },
    NeedsHostKeyApproval { fingerprint: HostKeyFingerprint },
    NeedsPassword,
    NeedsPassphrase,
}
#[derive(Debug, thiserror::Error)]   // `thiserror` como dependencia de `application`; mensajes literales sin secretos
pub enum ConnectError {
    #[error("the host key has changed")] HostKeyChanged { fingerprint: HostKeyFingerprint },
    #[error(transparent)] Transport(#[from] TransportError),
    #[error(transparent)] Key(#[from] KeyError),
    #[error(transparent)] HostKey(#[from] HostKeyError),
    #[error(transparent)] Secret(#[from] SecretError),
}
```
Añadir `thiserror = "2"` a `[dependencies]` de `crates/application/Cargo.toml` → **3.er archivo** a modificar.

**Reglas de `execute`:**
1. `transport.connect(&session.host)` → `Connected { id, fingerprint }`.
2. `verifier.verify(host, fp)`: `Known` → sigue. `Unknown` → si `approved_fingerprint == Some(fp)` → `verifier.trust(host, fp)` y sigue; si no → `close` + `Ok(NeedsHostKeyApproval { fp })`. `Changed` → `close` + `Err(HostKeyChanged { fp })` (**nunca** se hace `trust` en este caso, aunque venga `approved_fingerprint`).
3. Credencial: `Password { remember }` → `request.password`, o si es None y `remember` → `secrets.get(SecretKey { session.id })`; si no hay ninguna → `close` + `Ok(NeedsPassword)`. `PublicKey { key, .. }` → `keys.load(key, request.passphrase)`: `PassphraseRequired` → `close` + `Ok(NeedsPassphrase)`; otro error → `close` + `Err(Key(..))`.
4. `transport.authenticate(id, credential)`; error → `close` + `Err(Transport(..))`.
5. `transport.open_pty(id, pty_size, sink)`; error → `close` + `Err`. Éxito → `Ok(Connected { connection: id, channel })`.
6. Ninguna credencial se envía antes de que la huella sea `Known` o aprobada (test con `mockall::Sequence`).

**Criterios de aceptación (verificables por test con mocks):**
- [ ] Ruta feliz con contraseña tecleada y con llave → `Connected`; orden `connect → verify → (trust?) → authenticate → open_pty` verificado con `Sequence`.
- [ ] Huella `Unknown` sin aprobación → `NeedsHostKeyApproval`, `authenticate` no se llama y `close` sí.
- [ ] `Unknown` con la misma huella aprobada → `trust` una vez y conecta; aprobada pero **distinta** → `NeedsHostKeyApproval`.
- [ ] `Changed` → `Err(HostKeyChanged)`, sin `trust` ni `authenticate`, aun con `approved_fingerprint`.
- [ ] `remember = true` sin contraseña tecleada → usa `SecretStore::get`; sin nada guardado → `NeedsPassword`.
- [ ] `remember = false` sin contraseña → `NeedsPassword` y `SecretStore` no se consulta.
- [ ] Llave cifrada sin passphrase → `NeedsPassphrase`; passphrase incorrecta → `Err(Key(WrongPassphrase))`; ambos cierran la conexión.
- [ ] `AuthenticationRejected` y fallo de `open_pty` → error y `close` llamado.
- [ ] `format!("{err}")` de `ConnectError` no contiene secretos (test con contraseña conocida).
- [ ] `application` solo depende de `tuki-core` y `thiserror`; tests con el `block_on` mínimo (sin runtime).

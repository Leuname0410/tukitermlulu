## T-34b: Export a diagnostic file
**Fase:** F7  **Depende de:** T-34a
**Contexto:** El usuario pulsa **"Exportar diagnóstico"** y se genera `tukitermlulu-diagnostico-<AAAAMMDD-HHMMSS>.txt` en la carpeta de Descargas. El archivo contiene:
- la versión de la app (`env!("CARGO_PKG_VERSION")`);
- el SO y la arquitectura (`std::env::consts::{OS, ARCH}`);
- las últimas **2000 líneas** del log más reciente de `app_log_dir()`, ya redactadas por T-34a.

Sin dependencias nuevas y sin `zip`.

**Archivos a crear/modificar:**
- `crates/desktop/src/diagnostics.rs` (crear)
  - `fn build_report(version, os, arch, log_dir: &Path, max_lines) -> io::Result<String>`: pura salvo la lectura del directorio, y testeable.
  - Comando `export_diagnostics(app) -> Res<String>`: devuelve la ruta escrita y reutiliza la resolución de Descargas de `sftp::downloads_dir`.
- `crates/desktop/src/main.rs` (modificar: `mod diagnostics;` y registrar el comando)
- `ui/src/lib/api.ts` + `ui/src/lib/api.test.ts` (modificar: `exportDiagnostics(): Promise<string>`)
- `ui/src/App.tsx` (modificar: botón "Exportar diagnóstico" junto a `QuickConnect`; muestra la ruta en un `role="status"` o el error en un `role="alert"`)

**Reglas:**
- El log más reciente es el `tukitermlulu*.log` con mayor fecha de modificación.
  - Sin logs, el informe dice `(sin logs)` y no es un error.
- Lectura por streaming de líneas, conservando las últimas N en un `VecDeque` (no cargar en memoria un log de cientos de MB).
- Antes de escribir, el informe pasa **otra vez** por la redacción. Se reemplaza `<campo>=<valor>` cuando el nombre del campo es sensible, reutilizando `is_sensitive` de `logging.rs` (puedes hacerlo `pub(crate)`). Es una defensa en profundidad para logs escritos por versiones anteriores.
- El archivo se crea con `create_new`.
  - Si el nombre ya existe (dos clics en el mismo segundo), se añade `-1`, `-2`, etc.
- Errores tipados al estilo de los demás comandos, sin rutas absolutas del usuario en el mensaje. Nada de `unwrap`/`expect`.

**Criterios de aceptación:**
- [ ] `build_report` con un directorio temporal:
  - incluye la versión, el SO y la arquitectura;
  - toma solo el log más reciente;
  - con 2500 líneas, conserva las últimas 2000;
  - sin logs, `(sin logs)`.
- [ ] Una línea `password=abc host=srv` en el log aparece como `password=[REDACTED] host=srv`.
- [ ] Dos exportaciones seguidas con el mismo nombre → dos archivos distintos y ninguno se sobrescribe.
- [ ] UI (Vitest con la API mockeada): el clic llama a `exportDiagnostics` y muestra la ruta; si falla, muestra el error.
- [ ] `just check` en verde.

**Commits:** `test(desktop): diagnostic report [T-34b]` → `feat(desktop): export diagnostic report [T-34b]`

**Fuera de alcance:** enviar el diagnóstico a un servidor (nunca), comprimir y adjuntar la configuración.

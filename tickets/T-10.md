## T-10: Implement the keyring SecretStore and an in-memory fake
**Fase:** F2  **Depende de:** T-09 · **ADR:** 004 (solo contraseñas de sesión)
**Contexto:** Contraseñas de sesión en el almacén del SO (Credential Manager / Secret Service / Keychain) vía `keyring`, más un fake en memoria reutilizable por otros tests. Nada en disco en claro.

**Archivos a crear/modificar:**
- `crates/adapters/Cargo.toml` (modificar: `keyring = { version = "3", features = ["windows-native", "apple-native", "sync-secret-service", "crypto-rust"] }`; si `cargo deny` rechaza alguna licencia transitiva, detente y repórtalo)
- `crates/adapters/src/lib.rs` (modificar: `pub mod secret_store;`)
- `crates/adapters/src/secret_store.rs` (crear: `KeyringSecretStore` + `InMemorySecretStore`)
- `crates/adapters/tests/secret_store.rs` (crear)

**Interfaces / firmas esperadas:**
```rust
pub struct KeyringSecretStore { service: String }        // new(service: &str); la app usará "tukitermlulu"
pub struct InMemorySecretStore { /* Mutex<HashMap<SessionId, Zeroizing<String>>> */ }   // Default
// ambos: impl tuki_core::ports::SecretStore
// entrada de keyring: service = self.service, user = format!("session-{}", key.session.get())
```
- Las llamadas a `keyring` son bloqueantes → `tokio::task::spawn_blocking`.
- `get` sin entrada → `Ok(None)`; `delete` sin entrada → `Ok(())` (idempotente); `NoStorageAccess`/`PlatformFailure` sin backend → `SecretError::Unavailable`; resto → `Io`.
- El `String` devuelto por keyring se envuelve de inmediato en `SecretString`; ningún `Debug` del adaptador muestra valores.

**Criterios de aceptación (verificables por test):**
- [ ] `InMemorySecretStore`: set → get devuelve el valor; set de nuevo reemplaza; delete → get `None`; delete repetido → Ok.
- [ ] `KeyringSecretStore` ida y vuelta (set/get/replace/delete) con un `service` único por test (`tukitermlulu-test-<uuid o timestamp>`), limpiando al final. Marcado `#[ignore = "requires OS keyring"]` (se ejecuta con `cargo test -- --ignored`; verificado en Windows).
- [ ] `format!("{:?}", store)` no contiene secretos (test sobre el fake con un valor cargado).
- [ ] Sin `unwrap`/`expect` en producción (el `Mutex` envenenado → `SecretError::Io`).

**Tests requeridos:** integración (`#[tokio::test]`).
**Commits:** `test(adapters): secret store round trips [T-10]` → `feat(adapters): keyring and in-memory secret stores [T-10]`

**Fuera de alcance:** fallback cifrado con contraseña maestra (riesgo §8, futuro ticket), passphrases de llave (ADR-004), receta de `justfile`.
